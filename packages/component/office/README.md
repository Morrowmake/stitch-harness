## Use this package

In Web or Desktop, open Plugins and switch **Office documents** on or off, or choose a component set with the first-run component picker. The `web` profile template selects the Standard set.

<a id="understand-the-implementation"></a>
## Understand the implementation

<details>
<summary>Implementation details — click to expand</summary>

[`cordis.patch.yml`](cordis.patch.yml) switches on the rows that [dsh-web-app](../../bundle/web-app/README.md) keeps disabled with a `# component: office` mark, and mounts the `component-office` marker row that opens the `component: office` gates of the [agent presets](../../preset/agent-preset-registry/README.md). The rows keep their ids, positions, and configuration in dsh-web-app and dsh-base, so later profile patches address them as before.

Host and browser rows it switches on: `office-kit`, `workspace-dependencies`, `skill-office`.

Preset rows gated on it: `present`, `tool-office`.

</details>

<a id="model-experience"></a>
## Model Experience

Indirectly, through the Office skills, the Office document tools, and the `present` tool it adds to the presets that list them.

#### KV Cache effect

Switching the component changes the composition of sessions created afterwards; existing sessions keep the preset revision they started with.
