## Use this package

In Web or Desktop, open Plugins and switch **Goals** on or off, or choose a component set with the first-run component picker. The `web` profile template selects the Standard set.

<a id="understand-the-implementation"></a>
## Understand the implementation

<details>
<summary>Implementation details — click to expand</summary>

[`cordis.patch.yml`](cordis.patch.yml) switches on the rows that [dsh-web-app](../../bundle/web-app/README.md) keeps disabled with a `# component: goals` mark, and mounts the `component-goals` marker row that opens the `component: goals` gates of the [agent presets](../../preset/agent-preset-registry/README.md). The rows keep their ids, positions, and configuration in dsh-web-app and dsh-base, so later profile patches address them as before.

Host and browser rows it switches on: `goal`, `goal-round-driver`, `ui-goal`.

Preset rows gated on it: `command-goal`, `tool-goal`.

</details>

<a id="model-experience"></a>
## Model Experience

Indirectly, through the goal tools and their prompt guidance it adds to the Standard, PTC, and Creator presets; `/goal` drives follow-up rounds.

#### KV Cache effect

Switching the component changes the composition of sessions created afterwards; existing sessions keep the preset revision they started with.
